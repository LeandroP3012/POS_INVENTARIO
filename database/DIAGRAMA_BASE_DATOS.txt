╔═══════════════════════════════════════════════════════════════════════════╗
║                              📊 VISTA: sales_detail                        ║
╚═══════════════════════════════════════════════════════════════════════════╝

    SELECT 
        s.id,
        s.sale_number,
        s.sale_date,
        s.total_amount,
        s.status,
        s.payment_method,
        u.username as cashier_username,
        u.full_name as cashier_name,
        COALESCE(c.name, 'Cliente Genérico') as customer_name,
        COALESCE(c.document_number, '00000000') as customer_document,
        COUNT(si.id) as items_count,
        SUM(si.quantity) as total_items_qty
    FROM sales s
    INNER JOIN users u ON s.user_id = u.id
    LEFT JOIN customers c ON s.customer_id = c.id
    LEFT JOIN sale_items si ON s.id = si.sale_id
    GROUP BY s.id;

╔═══════════════════════════════════════════════════════════════════════════╗
║                           📈 FLUJO DE DATOS TÍPICO                         ║
╚═══════════════════════════════════════════════════════════════════════════╝

1. INICIALIZACIÓN
   └─► system_config cargada al iniciar la aplicación

2. AUTENTICACIÓN
   users → roles → permissions
      └─► user_sessions (nueva sesión)
      └─► activity_logs (registro de login)

3. CARGA DE PRODUCTOS
   products → categories + suppliers
      └─► Filtro por active = TRUE
      └─► Filtro por current_stock > 0

4. VENTA
   ┌─ Seleccionar productos
   │  └─► products (consulta)
   │
   ├─ Agregar al carrito
   │  └─► Almacenamiento temporal en memoria
   │
   ├─ Calcular totales
   │  ├─► Subtotal (suma de productos)
   │  ├─► IGV (según system_config.tax_rate)
   │  └─► Total (subtotal + IGV - descuento)
   │
   ├─ Procesar pago
   │  ├─► Validar monto pagado
   │  ├─► Calcular vuelto
   │  └─► Seleccionar método de pago
   │
   └─ Guardar venta
      ├─► INSERT INTO sales (cabecera)
      ├─► INSERT INTO sale_items (detalle) × N productos
      ├─► INSERT INTO sale_payments (pago)
      │
      └─► Actualizar inventario
          ├─► UPDATE products.current_stock
          └─► INSERT INTO inventory_movements

ALTO RENDIMIENTO (Búsquedas frecuentes):
  ├─ products.barcode          → Búsqueda por código de barras
  ├─ products.code             → Búsqueda por SKU
  ├─ products.name             → Búsqueda por nombre
  ├─ sales.sale_number         → Búsqueda de venta específica
  ├─ sales.sale_date           → Reportes por fecha
  └─ users.username            → Login de usuarios

RENDIMIENTO MEDIO (Reportes):
  ├─ sale_items.sale_id        → Detalle de ventas
  ├─ sale_items.product_id     → Productos más vendidos
  ├─ inventory_movements.product_id  → Historial de movimientos
  └─ customers.document_number → Búsqueda de clientes

INTEGRIDAD REFERENCIAL:
  ├─ Todos los campos con 🔗
  └─ Aseguran consistencia de datos


╔═══════════════════════════════════════════════════════════════════════════╗
║                         💾 TAMAÑOS APROXIMADOS                             ║
╚═══════════════════════════════════════════════════════════════════════════╝

Base de datos vacía:        ~2 MB
Con 1,000 productos:        ~5 MB
Con 10,000 ventas:          ~20 MB
Con 100,000 ventas:         ~150 MB
Con logs (1 año):           +50 MB

Recomendaciones:
  ├─ Purgar activity_logs periódicamente (>90 días)
  ├─ Archivar ventas antiguas (>1 año)
  └─ Optimizar tablas mensualmente

products.current_stock
  └─► Actualizado automáticamente en cada venta
  └─► NUNCA modificar manualmente (usar inventory_movements)

sales.total_amount
  └─► Calculado: subtotal + tax_amount - discount_amount
  └─► Almacenado para consistencia histórica

system_config.next_sale_number
  └─► Auto-incrementa para generar sale_number
  └─► Formato: VTA-{YYYY}-{NNNNN}

users.password_hash
  └─► SHA2(password, 256)
  └─► NUNCA almacenar contraseñas en texto plano
